# Ruff — шпаргалка по командам

Ruff уже установлен и настроен в этом проекте (`pyproject.toml`,
секции `[tool.ruff]`). Два инструмента в одном пакете: **линтер**
(ищет проблемы в коде) и **форматтер** (причёсывает стиль). Теория —
в `01_junior/2.6_typing/07_pep8_formatting_linting_demo.py`, здесь —
только команды, которыми реально пользоваться день в день.

## Разница с pyright

| Инструмент | Проверяет | Пример находки |
|---|---|---|
| `pyright` | ТИПЫ | ожидался `int`, а вернули `str` |
| `ruff check` | КАЧЕСТВО КОДА | неиспользуемый импорт, `== None` вместо `is None`, мутабельный default |
| `ruff format` | СТИЛЬ (не ищет ошибки, просто переписывает) | пробелы, перенос длинных строк, кавычки |

Все три — независимые инструменты, гоняются по очереди, не заменяют
друг друга.

## Рабочий цикл на одном файле

Написал код в файле → перед тем как сказать "готово, проверь":

```
ruff format путь/к/файлу.py     # 1. причесать стиль — безопасно всегда
ruff check  путь/к/файлу.py     # 2. проверить на реальные проблемы
npx pyright путь/к/файлу.py     # 3. проверить типы (как раньше)
python      путь/к/файлу.py     # 4. запустить и посмотреть на вывод
```

`ruff format` можно гонять когда угодно без раздумий — он не меняет
смысл кода, только внешний вид (в отличие от `ruff check --fix`,
который стоит хотя бы раз просмотреть перед применением).

## Основные команды

```
ruff format путь/к/файлу.py       # отформатировать один файл
ruff format .                     # отформатировать весь проект

ruff check путь/к/файлу.py        # проверить один файл (только отчёт)
ruff check .                      # проверить весь проект

ruff check --fix путь/к/файлу.py  # проверить И исправить то, что
                                   # ruff умеет чинить сам (не всё)

ruff check . --statistics         # сводка: сколько находок и каких
                                   # кодов (E501, F401, B006 и т.п.)
```

## Как читать находку `ruff check`

```
файл.py:12:1: F401 'os' imported but unused
```

- `12:1` — строка и колонка
- `F401` — код правила (F = pyflakes, E/W = pycodestyle, B = bugbear)
- текст после кода — что не так

## Подавить одну конкретную находку (только для намеренного кода)

```python
some_code()  # noqa: F401
```

Использовать ТОЛЬКО когда находка — не баг, а осознанное решение
(например, в демо-файле специально показывается плохой паттерн).
Для реальных проблем — чинить код, а не подавлять предупреждение.

## Если что-то непонятно в выводе

Покажи мне (или спроси в чате) — код правила (`E501`, `F401`, `B006`
и т.д.) всегда можно объяснить конкретно, что он проверяет и почему.
