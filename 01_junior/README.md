# 🟢 Junior Level — Стажёр → Junior

> Путь от первого класса на Python до самостоятельного backend-разработчика

## Где смотреть актуальный статус

Этот файл **не** дублирует прогресс — он его быстро гниёт (было уже
один раз: старая версия этого README называла блоками то, чего давно
не существует). Актуальное состояние всегда здесь:

- **`PROGRESS.md`** (корень репозитория) — что пройдено, дата
  последней сессии, что дальше
- **`PYTHON_BACKEND_ROADMAP.md`** (корень репозитория) — полный список
  тем блока, критерии перехода на Middle, чек-листы самопроверки
- **`assessments/`** (корень репозитория) — финальные оценки блоков

## Вход в уровень

Требований нет — Junior/стажёрский уровень открыт с нуля. Единственное
ожидание: готовность заниматься 10–15 часов в неделю в течение
4–6 месяцев (см. `PYTHON_BACKEND_ROADMAP.md`).

## Чекпоинт: Стажёр → Junior

Это не формальный тест и не строка в чек-листе — решение ментора,
основанное на наблюдаемом поведении в сессиях, а не на количестве
пройденных блоков (см. `.claude/skills/senior-backend/SKILL.md`):

- Пишет код сам, не копируя паттерн из демо-файла без понимания, зачем
  он так устроен
- Находит и чинит свои ошибки без наводящих вопросов ментора
- Может объяснить, ПОЧЕМУ код работает именно так — не только что он
  делает
- Правки по коду (порядок логики, соответствие условию задания,
  опечатки) с каждой сессией случаются реже

Пока это не так стабильно — уровень называется "стажёр", даже если
формально пройдено много блоков. Момент повышения — отдельное явное
объявление ментора, не тихое переименование.

## Выход из уровня: Junior → Middle

Полный и единственный источник правды — раздел «Критерии перехода на
Middle» и «Сводный чек-лист Junior → Middle» в
`PYTHON_BACKEND_ROADMAP.md`. Коротко, о чём он:

- Идиоматичный Python без копирования из туториалов (comprehensions,
  контекстные менеджеры, `dataclasses`)
- Понимание `is`/`==`, mutable/immutable, ловушки mutable default
- Уверенный SQL с JOIN-ами + понимание, что генерирует ORM
- 2–3 законченных pet-проекта, один — REST API с БД
- Все блоки 2.1–2.10 пройдены (финальные оценки в `assessments/` —
  ≥80%)
