# Реляционная модель и маппинг — базовые понятия

## Реляционная модель данных

Способ организации данных в виде **таблиц** (отношений, *relations*), где:

- строки — это отдельные записи (например, один пользователь);
- столбцы — это атрибуты записи (имя, возраст, email);
- связи между таблицами строятся через **ключи** (первичный ключ в одной таблице ссылается на внешний ключ в другой).

Слово «реляционная» идёт от английского *relation* — это математический термин, означающий именно таблицу с чётко заданной структурой (не от слова «отношения» между людьми, как иногда путают).

**Мнемоника:** реляционная = табличная + связанная по ключам.

Отсюда и «Object-**Relational** Mapping» — маппинг между объектами Python и этими самыми таблицами-отношениями.

---

## Маппинг (mapping)

«Отображение» или «сопоставление» одного набора сущностей другому, по принципу: элементу A однозначно соответствует элемент B.

В контексте ORM это означает:

- **класс Python** ↔ **таблица в БД**
- **атрибут объекта** ↔ **столбец таблицы**
- **экземпляр класса** ↔ **строка (запись)** в таблице

Пример:
```python
class User(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True)
    name = Column(String)
```
Здесь класс `User` замапплен на таблицу `users`, а атрибут `name` — на столбец `name`.

**Мнемоника:** маппинг = «перевод» между двумя языками — языком объектов (Python) и языком таблиц (SQL). ORM работает переводчиком в обе стороны: когда вы создаёте объект — он превращается в SQL INSERT, а когда делаете запрос — строки таблицы превращаются обратно в объекты.
